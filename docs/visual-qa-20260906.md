## Palette and typography checks

Warm, Neutral and Cool were each visually compared in Light and Dark at the same 768×900 Appearance page. Warm gives the page, cards, control edges and navigation a consistent cream/taupe or warm-brown treatment. Cool uses slate-blue surfaces. Neutral retains the existing identity. Semantic and module colors remain recognizable. The same shared palette is used by the additional Warm/Dark Calendar, Meals, notification and wall checks; the notification screenshot used Neutral/Dark.

Serif was verified on actual recipe titles, prominent page/modal headings, and wall clock/date. Dense metadata, inputs, selectors, ingredient text, buttons and navigation remain Sans. Default was visually inspected before switching. This is a heading option, not full-page serif text. Reader deliberately retains its no-JavaScript, light presentation.

The focused tests measure primary/secondary/tertiary text, semantic and module foreground tokens on their specified reading surfaces in all six palettes. They also check focus and control boundaries. These measurements are not a claim of complete WCAG conformance, all category-color combinations, browser zoom, or assistive-technology compatibility.

## Concrete before / after refinements

1. **Mobile Task details:** the previous Add subtask control shrank to an intrinsic width and wrapped “Add” and “subtask” despite spare row space. The participant picker also competed with its action. Both containers now fill the row; compact participant actions stack beneath the selector. The 390px screenshot confirmed a full-width selector, one-line Add subtask, and visible Close/Edit controls. The suspected Close clipping from an earlier capture was a settling artifact; no header workaround was introduced.
2. **Form boundaries:** the first browser style measurement exposed an override that a base-token-only check missed: `glass.css` restored decorative `--color-border` after `layout.css`. Both actual input rules now use `--color-border-control`. A subsequent Activity form screenshot and computed style confirmed Warm light border `rgb(148, 129, 106)` against working surface `rgb(253, 251, 247)`. Tests now cover both surface and working surface in every palette and protect both stylesheet rules. Card borders were not strengthened.
3. **Meal toolbar:** the parallel root QA recorded mismatched selector heights and a horizontal toolbar rail at 390px before its bounded CSS fix. The subsequent mobile visual pass confirmed aligned Person/context selectors, wrapped actions and readable context guidance. Context semantics were tested separately.

## Remaining visual/product follow-up

- Kanban gives zero-point metadata substantial space beside titles. At desktop and tablet widths, even ordinary task titles truncate early in 300px cards. A future presentation decision can move or de-emphasize the points without changing reward semantics. No card redesign was added during final QA.
- Trips still use raw ISO date/time strings and internal-looking words such as `vacation` and `planning`; Activity categories also expose terse keys. Format these through existing locale/date helpers in a focused copy pass, with timezone fixtures. This does not invalidate itinerary functionality.
- Desktop list modules intentionally use a narrower reading column than Places/Trips. The resulting density difference is visible but does not justify removing features or a layout rewrite.
- Physical iOS/Android devices, touch gestures, screen readers, browser zoom at 200%, actual e-paper hardware, offline/reconnect and background Web Push need separate device testing. The six palettes were compared on a shared settings surface; every module was not tested in all six combinations. Reader did not receive a new Dark contract.
