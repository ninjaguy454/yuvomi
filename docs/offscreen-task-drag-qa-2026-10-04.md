# Offscreen subtask pool dragging

The original acceptance pointer handler highlighted visible pools but did not scroll the allocation dialog during a held drag. A regression fixture with 12 subtasks and ten assignees (11 pools including Unassigned) failed at 320px and 390px touch emulation and 1280px desktop mouse: the last assignee began below the dialog and edge holding never advanced the scroll position.

The scoped fix scrolls only the modal body while the captured pointer remains near its upper/lower edge. Drop highlighting is recalculated as pools move underneath the pointer. Scrolling stops on release, cancellation, Escape, lost capture, rerender or authentication-context termination. The frame loop checks capture ownership itself because touch capture-loss events can be deferred while a pointer is stationary. No draft assignment or API mutation occurs until the existing drop/confirmation flow.

Three registered browser stress cases use real Chromium mouse/touch input and production components/CSS against synthetic API projections. They traverse the long list without wheel events or scripted scroll changes during the traversal, drop into the initially offscreen tenth assignee, verify cancellation/capture loss/session ending leave no stuck scroll or unwanted assignment, and confirm exactly one payload retaining all 12 subtask entries. A second subtask is assigned using keyboard Space, End, Enter on the labelled native Assign-to select; focus follows the relocated control. Both chosen subtasks target assignee ten; all others remain unassigned. The original 15 acceptance interaction cases remain in the same suite.

Six screenshots (drag and keyboard result at each width) were visually inspected. At 320px the closed native select truncates its long selected label, while the containing pool heading clearly identifies the full assignee; selection remains available through the native control. Existing global navigation wrapping at 320px is a minor pre-existing presentation issue: controls remain separately visible and usable, and it does not obstruct the acceptance modal or assignment flow.

Scope: Chromium viewport/touch emulation with synthetic data, not physical-device or cross-browser certification. Authentication-context cleanup uses the actual client event; real server-side context authorization remains covered by the separate acceptance backend suites. Phase 2 and all backend task semantics are unchanged. Final image identities, test counts and repeated recovery evidence are recorded in the handoff release metadata.
